# Behavior card — LZMA NCD

Source: `textdistance/algorithms/compression_based.py` (`LZMANCD`, via `_BinaryNCDBase` and `_NCDBase`)
Target: `rust/src/algorithms/compression/lzma_ncd.rs`
Original tests: **none dedicated** — see "worked examples" below.

## What it does

Same NCD formula as BZ2 NCD (see `docs/behavior-cards/manasa/bz2-ncd.md`),
using the LZMA compressor as the size estimator instead of bz2:

```text
NCD(a, b) = (C(a+b) - min(C(a), C(b))) / max(C(a), C(b))
```

`LZMANCD._compress` calls `lzma.compress(data)` and strips the first
**14 bytes** (the LZMA stream header) before measuring length. If the
`lzma` stdlib module fails to import, the source raises
`ImportError('Please, install the PylibLZMA module')` at call time.

## Inputs / options

- No constructor options, same as BZ2 NCD (`_BinaryNCDBase.__init__` is
  `pass`). No `qval`, no q-gram behavior.
- Accepts `str` (UTF-8 encoded before compression) or `bytes` (passed
  through unchanged).
- `maximum()` is always `1`.

## Edge cases

- Empty/empty: `0.0` (verified below — LZMA header overhead cancels out
  cleanly for empty input).
- Very short strings: see the coverage gap noted below — LZMA's fixed
  header/dictionary overhead can dominate the signal entirely.

## ⚠️ Zero frozen test coverage — read before implementing

Unlike every other algorithm in this project, **`tests/original/` has no
dedicated test file for LZMA NCD**, and `test_compression/test_common.py`
*explicitly excludes* `lzma_ncd` from its shared property tests (symmetry,
monotonicity, normalization) with the comment `# too slow, makes CI flaky`.
Confirmed by grepping the entire `tests/original/` tree for `lzma` — the
only hit is that one commented-out line. There is no ground truth to check
against from the frozen suite at all.

## Worked examples — generated, not frozen

Because no frozen examples exist, these were generated by running the
**actual, unmodified** `textdistance.lzma_ncd` from this repo's own
`textdistance/` package (not a guess, not derived from `tests/original/`).
Treat these as a reasonable baseline to test against, but with less
authority than a frozen fixture — if the port's result differs, that's not
automatically a bug the way a `tests/original/` mismatch would be.

| left | right | observed |
| --- | --- | --- |
| `''` | `''` | `0.0` |
| `test` | `test` | `0.08695652173913043` |
| `test` | `text` | `0.08695652173913043` |
| `test` | `nani` | `0.08695652173913043` |
| `hello` | `haloa` | `0.08` |

**Notable quirk:** `test`/`test`, `test`/`text`, and `test`/`nani` all
produce the *identical* score. LZMA's fixed compression overhead dominates
at this input size, so the algorithm doesn't meaningfully discriminate
between "identical," "similar," and "different" for very short strings.
This still technically satisfies the project's `test_monotonicity` pattern
(`same <= similar <= different`, since equality satisfies `<=`), but it
means LZMA is a weak similarity signal for short inputs — a source
characteristic to preserve faithfully in the port, not a bug to "fix."

## Numeric tolerance

No frozen tolerance to match. Recommend the same standard as the rest of
the project (`isclose`-equivalent, `rel_tol ≈ 1e-9`) against the generated
values above, understanding they're a softer target than a real fixture.

## Dependencies / compressor settings

- Python side: stdlib `lzma` module, default settings, optional import
  (guarded by `try/except ImportError` in the source).
- Rust side: no crate chosen yet. Candidate: `xz2` (liblzma binding) or a
  pure-Rust LZMA implementation if one proves reliable — goes in
  `docs/dependency-notes/manasa.md` (`MAN-09`) for Simha Teja to review,
  same as BZ2.

## Known risks

- **Zero frozen coverage** (see above) — the biggest risk for this
  algorithm isn't compressor byte-mismatch, it's that there's no
  independently-verified correctness target at all. Flag this explicitly
  in the `MAN-07` handoff so Suri/the team knows this algorithm's
  correctness rests on self-generated fixtures, not the frozen suite.
- Same exact-byte-match risk as BZ2 NCD: a Rust LZMA crate may not produce
  the same compressed length as Python's `lzma` module. Per the team's
  agreed fallback, document any deviation in `DECISIONS.md` rather than
  chasing byte-perfect parity.
- The `[14:]` header-strip is specific to Python's `lzma.compress()` output
  framing; a Rust crate's output framing may differ.
- Real-world test inputs for this algorithm should probably use longer
  strings than `tests/original`'s typical short examples, given the
  discrimination problem observed above — worth a note for whoever builds
  the differential corpus (`INT-04`).
