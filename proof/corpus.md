# Differential Fixture Corpus (INT-04)

**Status: FROZEN — 114 cases across 10 algorithms, all passing against the
Rust-backed package.**

This is the fixed proof corpus required by INT-04. It exists to catch future
regressions: if a later change to `python_adapter/**` or any Rust algorithm
file alters observable behavior for Suri's ten assigned algorithms, rerunning
`proof/verify_corpus.py` will fail instead of the drift going unnoticed.

## Category coverage

Every corpus file tags each case with one `category`, covering the set INT-04
requires: `empty`, `equal`, `different`, `unicode`, `integers`, `bytes`,
`multi_sequence`, `qvalue`, `options`, `edge_case`. Not every category applies
to every algorithm (e.g. MRA ignores `qval` entirely; Matrix does not split
its input by `qval` at all) — where a category is inapplicable, either it is
omitted or a case demonstrates *why* it's inapplicable (see `mra.json`'s
`edge-qval-ignored` case).

## Fixture format

Each `proof/corpus/<algorithm>.json` file has the shape:

```json
{
  "algorithm": "overlap",
  "cases": [
    {
      "id": "different-0",
      "category": "different",
      "inputs": ["test", "text"],
      "options": {},
      "expected": {
        "distance": 0.25,
        "similarity": 0.75,
        "normalized_distance": 0.25,
        "normalized_similarity": 0.75,
        "maximum": 1.0
      },
      "note": "optional provenance/caveat"
    }
  ]
}
```

- `inputs`: positional arguments passed to the algorithm. Plain strings/lists
  are JSON-native. `bytes` inputs are encoded as `{"__bytes_hex__": "..."}`
  since JSON has no byte-string type; `proof/verify_corpus.py` decodes this
  back to a real `bytes` object before calling the algorithm.
- `options`: keyword arguments passed to the class constructor (e.g. `qval`,
  `as_set`, `terminator`, `match_cost`).
- `expected`: one entry per common method actually exercised for that case —
  usually `distance`/`similarity`/`normalized_distance`/`normalized_similarity`/
  `maximum` for numeric algorithms, or `call`/`similarity` for the
  sequence-returning algorithms (Prefix, Postfix). `call` results that are
  `bytes` are hex-encoded the same way as bytes inputs.
- `Infinity`/`-Infinity` appear literally for Tanimoto's disjoint-sequence
  case (`log2(0) == -inf`). This is valid for Python's `json` module (used by
  both the generator and the verifier) but is not strict RFC 8259 JSON; if the
  corpus is ever consumed by a strict JSON parser, treat these as a known,
  intentional exception.

## Provenance

Values were sourced in order of preference:

1. **Reused directly from the already-existing native Rust tests**
   (`tests/algorithm_<name>.rs`), whose own comments document they were
   captured from the real, unmodified original Python implementation (either
   the matching file in `tests/original/` when one exists, or a direct run of
   `textdistance.<name>` when it doesn't). Overlap, Tanimoto,
   Ratcliff-Obershelp, BWT-RLE NCD, MRA, Prefix, Postfix, Length, and Identity
   fixtures follow this path — the corpus does not re-derive values that were
   already independently verified.
2. **Computed fresh** against the current Rust-backed `textdistance` package,
   for a small number of additional cases (integers, bytes, extra options)
   not already covered by the native tests, then cross-checked against the
   native-test values above wherever the same input pair appears in both.

No case in this corpus was generated by running the *original pure-Python*
algorithm implementation directly — per Rule 26 of the PRD ("do not call or
embed the original Python implementation at runtime"), that code no longer
executes anywhere in this repository's Python package after INT-01.

## Running the corpus

```sh
python proof/verify_corpus.py
```

This imports `textdistance` (Rust-backed since INT-01: every call in
`textdistance/algorithms/**` delegates to the compiled `textdistance_port`
PyO3 extension) and replays all 114 cases. It does **not** import, shell out
to, or otherwise depend on the original pure-Python algorithm implementations
at any point — satisfying INT-04's acceptance criterion. Current result:

```text
114/114 corpus cases passed (0 failed)
```

Exit code is `0` on full pass, `1` otherwise, so it is suitable for wiring
into a future `make verify` target (INT-08).

## Adapter regressions checked during corpus integration

Cross-checking the frozen values surfaced two adapter mismatches. Both are
fixed in the current working tree and are documented in
[`known-issues.md`](known-issues.md):

1. `Prefix`/`Postfix` output now preserves Python list/tuple shape for word and
   n-gram q-values.
2. Ordinary `list[int]` input is kept as integers; only actual Python `bytes`
   objects are treated as byte sequences.

The verifier result above is therefore a live check of the corrected adapter,
not a fixture workaround for either behavior.
